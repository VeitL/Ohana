# Economy Care Entrypoint Matrix

Last reviewed: 2026-06-14, Codex care-derivation executor architecture session after the product-owner two-state deletion decision.

Purpose: list every current entry family that can write care facts, care ledger, rewards, revisions, reminders, stock, or Oasis-derived state. The acceptance rule is not "the function name is allowed"; the caller must either enter a typed chokepoint result (`CareFactWriteDisposition` or an equivalent result with `didRecord` / `didWriteFact`) or be explicitly outside the care-completion reward family.

## Shared Rules

- Active care target: may write the care fact through the typed chokepoint. Reward, ledger, reminder, stock/defaults, UI success, revision, and Oasis derived writes must consume the same typed result.
- Deceased care target: whole command no-op. No fact, ledger, reward, revision success, reminder completion, stock/default mutation, UI success feedback, or Oasis derived write.
- Non-empty explicit executor id that is invalid, missing, physically deleted, non-writable, or deceased: must not drop the active care target fact. The fact is written under the user action; reward ownership uses explicit fallback to a writable active human, or fact-only/no reward when no owner is available. It must never pretend the dirty executor received the reward.
- Historical backfill: care fact uses the historical occurrence date; reward budget/cooldown and wallet ledger use the operation day.
- Shared care target resolution must use `EconomyWalletWritePolicy.canWrite`, which accepts only non-deceased active targets.
