## 1. 产品是什么

Ohana（夏威夷语“家人”——家人意味着没有人会被落下）是一个把“家”做成一座岛屿的照护应用：家庭成员（宠物为核心，也包括人和植物）住在岛上，日常照护被记录、被提醒、被奖励，最终沉淀为这个家的记忆与资产。

核心定义——家庭即生命组合：家庭不是“人类之间”的概念。任何多于一个生命的组合就是一个家庭——一个人和一只猫、一个人和三盆植物、一对夫妻和一条狗，都是完整的家庭/岛屿。
由此推论：心情、周报、名册、连胜、排行榜等一切“家庭感”功能不以多人类为前提；产品永远不得出现“添加更多人类成员才完整”的暗示。免费用户必须能完成一个小型家庭的基本照护；付费卖的是更大规模、更省心的本地工具、多操作者协作和高级智能，不是“家庭”资格或用户已有的照护记忆。

一句话定位：

认真记录照护的家庭，值得一座越来越繁茂的岛。

产品的情感弧线：

日常（喂食、遛狗、清洁、用药）
→ 习惯（连胜、任务、提醒）
→ 惊喜（椰子、扭蛋、绿洲生长）
→ 沉淀（相册、里程碑、账本、周报）
→ 告别与铭记（彩虹桥、纪念模式）

最后一环是 Ohana 区别于工具型记录 app 的灵魂：这个 app 陪用户走完和宠物的一生。

## 2. 为谁做（首发画像）

* 主理人：家庭中承担主要照护责任的那个人，用自己的 iPhone 记录全家。
* 首发场景为单设备、单操作者、纯本地。
* 人类成员是被照护档案对象，不是首发阶段的 app 操作者；单主人版允许建立多个人类档案。
* 普通模式中植物进入首发成长线，但不在 Lv.1 立即展示；基础植物照护在 Lv.4「生命树冠」解锁，通过 PlantFeatureGate + PlantUnlockPolicy 控制可达面。佛系模式从第一天展示活跃植物，但不由此解锁普通模式的植物照护页面。
* 养宠家庭是 Lv.1–3 核心；养植物家庭在 Lv.4 扩展进入同一个家庭生命照护闭环。犬、猫为第一公民动物物种，其他动物使用通用浅模板。
* 商业模式采用可持续的 Freemium：
    * Ohana Free：单设备 / 单操作者 / 本地基础照护；免费额度为 1 个活跃宠物、2 个活跃 Human、5 株活跃植物和合计 3 个普通活跃提醒 / 计划。
    * 首发 Ohana Personal：解锁不限活跃档案和计划、高级本地功能与全部 Supporter 装饰；提供月付、年付和 Lifetime 买断。
    * 已验证有效的旧 Supporter Pack 购买直接 grandfather 为 Personal Lifetime，不要求老用户重复付费。
    * 未来 Ohana Family：包含 Personal，以订阅售卖多设备同步 + 多操作者协作。
    * 未来 Ohana Care+：包含 Personal，以订阅售卖 AI、智能洞察和植物智能照护；是否同时包含 Family 待验证。
    * Ohana 不植入第三方广告，也不销售“去广告”。

## 3. 根本决策（宪法条款）

| # | 决策 | 内容 | 直接后果 |
| --- | --- | --- | --- |
| D1 | 产品定位 | 家中所有生命首发成长线。Lv.1–3 先完成宠物核心照护习惯；Lv.4「生命树冠」把家庭扩展到植物，开放本地档案、任务、提醒、日志和资料库闭环。 | App Store 首发定位为家庭生命照护；首次引导不采集家庭偏好或请求权限，相关设置只在对应功能中按需出现；基础植物在 Lv.4 开放，Free 可同时管理 5 株活跃植物，Personal 不限量。 |
| D2 | 游戏化角色 | 记录为主，游戏化为留存引擎。椰子、连胜、绿洲、扭蛋用于强化照护习惯，但不做重度养成；真钱购买椰子暂不规划。 | 经济必须自洽防刷；冷却、每日预算、距离门槛等机制升格为产品规则；不引入付费货币合规负担。 |
| D3 | 钱包模型 | 成员钱包 + 岛屿储备 + 岛屿总账。照护等有明确归属的奖励进入成员独立钱包；不属于任何成员的系统赠礼进入 `system:island` 岛屿储备。岛屿总资产 = 岛屿储备 + 所有活跃成员钱包；排行榜只表达成员贡献。 | QuestManager 总余额必须恒等于 `system:island + Σ活跃成员 balance`；`system:legacy` 仍只作历史兼容且不计入正式资产；账本可重放；前台默认弱化复杂分账。 |
| D4 | 联网范围 | Free / Personal 的照护运行仍为纯本地 + 用户自有 iCloud Drive 受限备份/恢复；商业联网面使用 Apple StoreKit。唯一批准的开发者托管在线能力是用户主动启用的 Ohana Family App 内亲友守护，且必须通过独立运行开关和上线门禁；CloudKit 实时同步与家庭共享仍保持关闭。 | 普通功能不要求账号；离线用户可使用已授予的本地能力。Family 守护只传输最小安全信号，不能接触照护资料；AWS、APNs、Sign in with Apple、隐私标签、StoreKit 与双真机门禁未完成时，Family 入口和 SKU 保持关闭。 |
| D5 | 本机任务与在线协作边界 | Ohana Free / Personal 允许主理人在同一设备用 Human 档案记录家庭分工；普通分工默认 0 奖励并可直接完成，只有用户主动添加正数椰子奖励时才进入提交与发布者确认。这些角色是本地流程状态，不代表账号、远程操作者或对方已收到通知。远程邀请、跨设备实时共享/通知和权限仍属于真正在线协作。 | 本机家庭分工不经过 OnlineFeatureGate；外部协作路由、邀请、共享提醒、远程身份与权限继续受 OnlineFeatureGate 约束。奖励分工发布时须有足额余额，但发布不扣款、不冻结或托管，只有发布者确认完成时才执行转账。界面只呈现当前需要的下一步，不同时暴露负责人、完成人、审核人等整套角色。 |
| D6 | 首发模块范围 | 核心闭环必须成熟，不等于所有模块完整深度都上。首发优先打磨：建宠物 → 记录 → 提醒 → 奖励 → 首页反馈 → 备份；同时交付 Free / Personal 额度、购买、恢复和降级保护。 | Free 基础照护和 Personal 商业闭环都必须在首发前完成验收；任何尚未实现的 Personal 高级能力不得出现在销售页或 App Store 描述中；Family 和 Care+ 不进入 1.0。 |
| D7 | 纪念模式 | 照护只读，回忆可写。宠物 / 人类离世后，从所有活跃照护流程退场，不再生成任务、提醒、quest、奖励、连胜、心情信号；钱包冻结、历史保留。但允许新增纪念内容，如照片、回忆文字、纪念日、悼念笔记。 | 离世成员不得新增/编辑照护事实，不得补记历史照护事实，不触发任何经济或照护派生；纪念内容不进入经济系统。 |
| D8 | 删除哲学 | 确认后物理真删。删除成员时必须明确告知不可撤回；确认后物理删除该成员及其从属记录。取消用户可见软删除、回收站、30 天恢复。 | CloudSync 未来可保留用户不可见、不可恢复的 sync tombstone 元数据传播删除，但不得形成恢复 UI 或删除中转态。 |
| D9 | 免费/付费边界 | Ohana Free 免费并保留可独立完成的基础照护，对活跃档案和普通活跃提醒 / 计划设置清晰额度；Ohana Personal 以月付、年付或 Lifetime 解锁不限额度、高级本地工具和 Supporter 装饰；未来 Family 和 Care+ 只以订阅承担持续服务成本。Ohana 不植入广告。 | 首发付费理由必须同时覆盖“不限规模”与“更省心、更深入、更长期”的个人价值；不锁原始记录、已有历史、手动导出、健康关键提醒或纪念。 |
| D10 | 多人类档案与本机默认归属 | 单操作者版允许建立多个人类档案：Free 最多 2 个活跃 Human，Personal 不限。`currentActiveHumanId` 只是本机默认的任务视角与记录归属，不是操作者账号或登录身份。执行照护、记录数据或查看待办时优先无感使用该默认值。 | 没有在世 Human 时不伪造归属，只有 1 位时自动归属；两种情况都隐藏执行、记录、领取和审核等无意义控件。2 位以上时才提供轻量的单次覆盖，且覆盖只作用于本次操作，不改写全局默认。主动创建 Human 时姓名必填，性别和生日可选；不读取 Apple 账号资料，不以姓名或邮箱自动创建/合并档案。未来操作者身份仍须与 Human 分层。 |
| D11 | 备份命脉 | 自动 + 手动双保险。Free 保留最新一份自动 iCloud Drive 备份并永久允许手动导出；Personal 增加多版本自动备份和恢复点。两者使用统一的受限导出边界，不包含人类健康/HealthKit、PIN 机密和其他明确禁止离机的数据。备份失败必须可见，不许静默失效。 | 免费用户始终有最小数据安全网；多版本恢复属于 Personal 的长期安心能力，但不得用“完整”掩盖已批准的隐私排除。 |
| D12 | 补记奖励 | 补记历史记录照常奖励，但按操作日预算与冷却结算。补记 30 天前的 100 次喂食，最多拿到今天预算内的椰子。 | 诚实补记不受罚，刷子被预算兜住；发奖以 operation time 而非 record time 结算。 |
| D13 | 余额不足 | 不可透支 + 允许岛屿合资。任何钱包永不出现负余额；一般成员消费可选择从其他成员钱包补差额。Oasis 生命树注入是岛屿级消费，自动使用全部正式可用椰子：先扣岛屿储备，再按确定顺序由活跃成员钱包补足，并逐账户记录流水。 | 所有出资与扣款必须在同一事务中成功或整体回滚；账本仍可重放；排行榜贡献度语义不被污染。 |
| D14 | 预算触顶感知 | 温和透明。触顶后照护记录正常完成且有完成反馈，奖励位置显示温和文案，例如“今日椰子已装满，明天继续～”。 | 不隐瞒、不说教、不预告剩余额度；避免用户把限额当 bug，也不鼓励掐预算刷。 |
| D15 | 通知哲学 | 克制预算制。通知分三级：健康关键 > 日常照护 > 氛围提醒。健康关键不受每日限额；日常和氛围通知受限额、合并和夜间免打扰约束。 | 任何新通知必须先归类定级；通知预算表写入 Notifications-logic.md。 |
| D16 | 删除同步元数据 | 无用户可见回收站。未来 CloudSync 传播删除时，只允许保留不可见、不可恢复的 sync tombstone 元数据。 | tombstone 是同步协议事实，不是产品恢复能力。 |
| D17 | 首次体验 | 新安装先选择普通或佛系模式，再以 Human-first 建立本机本人。普通模式继续选择现在或以后建立宠物；佛系模式完成 Human 名称后直接进入三页 Shell，不要求宠物。 | 初次只要求模式与 Human 名字，不预先请求权限。普通模式保留 Pet → Home → 待办领取 50 椰子的流程；佛系在首次新增 Pet 或 Plant 后于 Oasis 显示同一家庭级 50 椰子领取卡。两个入口共用同一赠礼键，不得双领。旧用户默认普通模式并只显示一次可关闭的佛系介绍。 |
| D18 | 物种分层 | 犬猫深 + 其他浅。犬猫为第一公民；其他动物使用通用照护模板，不适用的深功能自动隐藏。 | 每本规则书标注模块的物种适用性。 |
| D19 | 植物功能门 | 普通模式的植物照护页面收进独立产品门、成长解锁门和商业额度门。佛系首页是明确例外：从第一天展示并允许新增、打卡和打开与普通模式相同的植物基础资料页；资料页只编辑档案字段，归档、恢复和删除继续走统一领域命令，不开放植物 Dashboard、浇水、施肥、提醒或时间线。Personal entitlement 只决定是否可超过 5 株活跃植物。 | 普通模式 Lv.1–3 植物入口 redirect 到 Growth Roadmap；佛系模式不得因等级隐藏植物卡片，也不得维护佛系专用植物管理列表；Free 仍最多 5 株活跃植物，Personal 不限；既有或降级后超额数据不得被隐藏。 |
| D20 | 多语言扩展就绪 | 当前九语言架构保持；新增语言的成本边界必须收敛为翻译资源文件 + 注册表若干 case + 商店元数据。 | 不允许功能代码散落语言判断；新增语言不应改业务逻辑。 |
| D21 | 植物商业边界 | 基础植物照护免费但通过成长解锁。Lv.4 后 Free 允许 5 株活跃植物的档案、浇水、施肥、修剪、换盆、照片、基础历史、资料库和导出；普通植物提醒与全 app 共用 3 个 Free 普通活跃提醒 / 计划额度。Personal 解锁不限活跃植物和计划；Family 售卖协作；Care+ 售卖智能。 | Lv.4 是体验节奏，不是付费墙；Free 达到数量上限后只阻止新增超额活跃对象，不隐藏已有数据、原始历史或导出。 |
| D22 | 数据与付费红线 | 用户取消 Personal 订阅、试用结束或商品加载、购买、恢复、验证失败后，必须仍可查看、编辑和手动导出本机已有数据；不得锁原始记录、已有历史、健康关键提醒、纪念模式或离世档案，不得卖椰子。 | 降级只限制新增超额活跃对象、新建高级产物和继续使用 Personal 工具；既有超额档案和计划不删除、不隐藏，已生成产物仍可查看与导出。旧 Supporter Pack 有效购买 grandfather 为 Personal Lifetime。 |
| D23 | 产品非目标 | Ohana 不是兽医诊断 app、不是重度游戏、不是公开社交网络、不是专业财务软件、不是儿童/老人监管系统、不是云同步优先产品。 | 所有新增需求必须先判断是否越界；越界功能不得进入首发。 |
| D24 | 首发平台范围 | 首发为 iPhone-only，最低系统 iOS 26.2；不发布原生 iPad 或 watchOS app。配对 Apple Watch 接收并操作由 iPhone 转发的系统通知属于真机兼容性验收，不等于原生 Watch app 支持。 | 所有首发 target 使用 iPhone device family；iPad、原生 Watch、Complication、独立 Watch 同步和更低 iOS 支持分别作为后续迁移，不得混入 RC 收尾。 |
| D25 | 账号按需、身份分层 | Free / Personal 不创建 Ohana 账号，也不读取系统账号资料。只有用户主动启用 Family 在线守护时，才通过 Sign in with Apple 建立最小远端 Account；Account、App 操作者和本机 Human 档案是三层不同身份，登录不得自动创建、合并或上传 Human。iCloud Drive 备份仍依赖用户自己的系统 iCloud 身份。 | Family 登录只服务邀请、守护关系、设备推送与签名权益，不得成为普通照护前置。用户可不登录继续本地使用；Human 绑定必须由用户显式确认。其他跨平台、CloudKit 家庭协作和完整账号能力仍须按 `docs/planning/account-backend-extension.md` 另行立项。 |
| D26 | 双 Shell 顶层区域 | 普通模式顶层区域固定为“首页 → 待办 → Oasis → 植物”，按成长解锁在末尾追加。佛系模式使用独立枚举与固定三页“首页 → Streak → Oasis”，不挂载普通待办、植物页或其他全局重型表面。 | 两个 Shell 共用领域事实、钱包、Oasis 与购买权益，但路由和 Tab 状态隔离。佛系首页统一管理 Human、Pet、Plant，Streak 是佛系专属顶层统计；普通模式仍不为一般数据统计新增 Tab。 |

### 4.2.1 家庭洞察与十级成长合同

规则固定为三句：

1. 基础记录尽早开放：Lv.1 即可记录体重、花费、单个成员或宠物的健康和用药。
2. 成长等级解锁新面板和玩法：Free 通过椰子树逐步获得家庭聚合、周报、深度分析、商店和收藏等能力。
3. Personal 提前开放家庭洞察：只绕过家庭洞察六个 Tab 的等级限制，不绕过其他成长门。

| 等级 | 名称 | 本级新增能力 |
| --- | --- | --- |
| Lv.1 | 照护种子 | 日常照护；单个对象健康与用药记录；家庭洞察“体重”“花费”；基础资料、文档和日历 |
| Lv.2 | 健康嫩芽 | 健康与用药的家庭聚合面板和基础趋势；记录能力仍属于 Lv.1 |
| Lv.3 | 成长枝条 | 时光记录、照片、成长时间线和成就 |
| Lv.4 | 生命树冠 | 普通模式植物管理 |
| Lv.5 | 绿洲收益 | Oasis 被动收益及生命树联动 |
| Lv.6 | 成果果实 | 椰子商店和标准家庭周报 |
| Lv.7 | 收藏玩法 | 扭蛋和收藏系统 |
| Lv.8 | 洞察树环 | 深度照护分析和完整提醒诊断 |
| Lv.9 | 记忆年轮 | 独立长期家庭回顾；不重复解锁周报 |
| Lv.10 | 大师树冠 | 电子宠物、最高树木收益和满级展示 |

家庭洞察 Tab 顺序固定为：`体重｜花费｜周报｜照护分析｜提醒健康｜长期回顾`。

* 体重和花费为两个独立 Tab，均在 Lv.1 开放；周报 Lv.6，照护分析和完整提醒诊断 Lv.8，长期回顾 Lv.9。
* Free 的体重与花费趋势提供 7 天、30 天和单对象查看；全部原始记录不按时间隐藏，仍可从对象历史查看、编辑和手动导出。
* Personal / Family 增加 90 天、1 年、全部时间、跨对象比较和聚合分析导出；Family 通过 `hasPersonal = Personal || Family` 继承。Family 在线守护独立读取 `hasFamily`，不改变洞察或成长规则。
* Lv.9 Free 长期回顾按月份整理全部既有照护事件与回忆，不展示长周期统计；Personal / Family 增加范围统计、对象比较与导出。
* 提醒权限异常、发送失败和逾期始终可见；详细调度流水和趋势仍由 Lv.8 或 Personal / Family 开放。
* 降级只锁回高级范围、比较和聚合导出；原始历史和已经达到的椰子树等级能力保持可用。

### 4.4 旧 Supporter Pack 迁移

## 6. 互通脊柱：业务事实流

用户动作
（首页长按 / QuickCare / 模块页 / 今日任务完成键 / 共享照护）
   ↓
domain service 写入一个 careTransaction
   ↓
单成员照护：通常生成一条业务事实
多成员共享照护：可生成多条子事实，但必须挂在同一个 careTransactionId 下
   ↓
由照护派生执行器统一裁决，且只发生一次：
   ├─ 今日任务勾掉
   ├─ 有归属椰子奖励 → 成员钱包 + 岛屿账本
   ├─ 无成员归属系统赠礼 → 岛屿储备 + 岛屿账本
   ├─ 连胜推进
   ├─ 成就 / 里程碑检查
   ├─ 相关提醒消除
   ├─ 库存 / 粮仓 / 账本派生
   ├─ Oasis XP / 绿洲反馈
   └─ 首页 / 仪表盘 revision 推进

入口可以很多，用户意图只有一个，事务必须唯一，派生只能发生一次。

同一个动作从不同入口完成，结果必须完全一致。
同一事实不得因为首页、QuickCare、任务完成键或模块页重复触发奖励、连胜、任务完成或账本派生。

## 7. 全局不变量

每本模块规则书必须逐条对照以下不变量。

### G1 一意图一事务，一事实只派生一次

一个用户动作必须生成一个唯一 careTransactionId。
单成员照护通常写一条业务事实；多成员共享照护可写多条子事实，但必须挂在同一个事务下。奖励、任务、连胜、提醒消除、库存变更、Oasis XP 等派生不得重复触发。

### G2 余额可重放

任何成员钱包及岛屿储备余额必须可由账本事实流重放推导。
岛屿总资产 ≡ `system:island + Σ活跃成员钱包`；`system:legacy` 不参与正式资产。
禁止任何视图直改余额；禁止绕过 QuestManager 底层奖励管线以及 EconomyRewardDiscipline / CareEventEconomyAwarding 等受审计收口发奖。

### G3 经济受预算管控

所有产出经过冷却 + 每日预算分档：

normal → fatigue 50% → recordOnly 0% → cooldown

记录永远允许，因为记录是产品心跳；被限制的是奖励，不是记录本身。

### G4 离世成员退场

离世成员：

* 数据保留
* 不再生成任务
* 不再生成提醒
* 不再生成 quest
* 不计入心情
* 不进入行动待办，也不生成系统建议
* 不推进连胜
* 不获得奖励
* 钱包冻结但历史可见
* 成员页可通过显示开关查看

每个模块的规则书必须写明本模块如何对待离世成员。

### G4.1 离世成员写入边界

* active 成员作为照护对象时，可写照护事实。
* 离世成员作为照护对象时，照护写入、编辑、历史补记和照护派生必须 no-op。
* 显式 executor id 不可解析、已被物理删除或不可写时，不得丢失 active 照护对象的事实。
* fallback 归属必须明确：
    * 优先归属可写 active human；
    * 没有可用 owner 时，fact-only 无奖励；
    * 不得伪装为原 executor 发奖。

### G4.2 纪念内容例外

离世成员允许新增纪念内容：

* 照片
* 回忆文字
* 纪念日
* 悼念笔记
* 纪念相册整理

纪念内容不得触发：

* 椰子奖励
* 连胜
* 今日任务完成
* 健康趋势
* 喂食 / 用药 / 遛狗等照护派生
* 活跃成员心情信号

### G5 删除即真删

成员与重要记录删除 = 明确确认后物理删除，用户不可恢复。
未来 CloudSync 仅可保留不可见、不可恢复的 sync tombstone 元数据用于跨设备删除传播，不得作为回收站或恢复能力。

### G6 隐私底线

数据默认仅存本机。
手动导出与自动备份必须完整覆盖“已批准的受限导出范围”，不得导出
人类健康/HealthKit、PIN hash/salt/lockout、自由文本家庭任务和可能重复敏感
文本的派生经济/账本侧车。“完整”不表示可以突破这一隐私边界。
“删除一切数据”为立即删除应用管理的本地用户内容、附件、偏好和反滥用
记录，不走回收站。对应用管理的 iCloud Drive 自动备份，删除失败必须显示
待清理状态并可重试；用户已主动分享或移出应用沙盒的副本不在远程擦除
承诺内。

### G7 单机自洽

首发版本不允许出现任何需要“另一个在线用户”才能完成或才有意义的流程：

* 邀请
* 加入岛屿
* 向远程操作者指派或推送任务
* 多人通知
* 实时协作
* 认领档案

这些能力必须收进 OnlineFeatureGate。

同一设备的本机家庭分工是记录能力，不是上述在线协作：主理人可用不同 Human
档案记录创建、执行和确认，但这些动作不证明对应人物实际操作或收到通知。普通分工
默认 0 奖励并直接完成；只有用户主动添加正数奖励时，才在余额足够的前提下进入提交 /
确认流程。发布只记录承诺，不扣款、不冻结、不形成 escrow，发布者确认完成时才从其
钱包转给完成者。远程邀请、跨设备实时共享/通知和权限仍须经过 OnlineFeatureGate。

### G8 工程质量

流畅性、本地化、无障碍、启动路径、能耗、架构隔离等遵循 AGENTS.md。
本文不重复工程细则，模块规则书引用即可。

### G9 家庭自洽

一个生命 + 主理人即完整家庭。
任何家庭感功能在单人单宠场景下必须完整成立，不残缺、不冷场、不暗示“添加更多成员才完整”。
排行榜在只有一个成员时应有得体的单成员形态。

### G10 备份命脉

自动备份默认开启。
备份失败必须对用户可见。
恢复路径必须被测试覆盖：

备份 → 擦除 → 恢复 → 数据完整

“陪你走完宠物一生”的产品承诺以此为底。

### G11 备份与删除一致性

应用内删除是当前数据库的不可恢复删除。
自动备份只保留有限版本，并在下一次成功备份后覆盖删除前状态。
手动导出的存档属于用户自持文件，应用不承诺远程擦除。
恢复旧存档前必须提示：

该存档可能包含你之后已经删除的数据。

### G12 付费状态不破坏本地数据

取消订阅、试用结束、商品加载失败、购买失败、交易未验证、恢复购买失败、退款或
交易撤销，都不得破坏本机已有数据或阻止 Free 基础能力。
最多停止新增超出 Free 额度的活跃对象 / 计划、新建 Personal 产物、Personal 专属外观、云同步、协作、共享提醒、云端版本历史和高级智能能力。
本地已有数据查看与编辑、原始历史、手动导出、健康关键提醒和纪念模式必须继续可用。
StoreKit 未知或不可用时，Free 基础能力 fail-open；不得把网络或 App Store 状态放进基础照护写入路径。已由椰子购买的商店物品使用独立所有权事实，不能因 Personal 状态变化而丢失、重复收费或被改写。

### G13 植物功能门独立

PlantFeatureGate 与 OnlineFeatureGate 不得耦合。
植物基础能力在 Lv.4 开放，Free / Personal 数量额度由独立权益策略裁决，Care+ 只增加智能能力；不得因为联机未解锁而阻止已解锁或 grandfather 的本地基础植物照护。

### G14 费用事实金额有效

用户输入、共享分摊、保费和文档派生费用必须是大于 0 的有限数字；0、负数、NaN
和正负无穷不得进入业务事实、导入或恢复。唯一负向例外是保险领域命令根据大于
0 的理赔金额生成的报销事实；它必须使用保险费用分类和稳定的报销标记，不得由
通用费用 UI 或通用费用命令伪造。失败必须发生在写入前，并允许用户修正后重试。

### G15 HealthKit 运动是只读外部事实

HealthKit 授权后，Human Workout 页面直接查询并展示当前可读的活动摘要与
`HKWorkout`，不要求用户再次导入，也不把只读 HealthKit 行伪装成 Ohana 可删除
记录。Ohana 手动运动和已完成遛狗保持各自的本地事实来源；统一 read model 按
HealthKit UUID、PetWalk ID 及时间、时长、距离匹配去重。既有本地 HealthKit / PetWalk
副本不得自动删除；实时来源可用时由其覆盖展示，来源不可用时允许本地副本兜底。
读取授权状态不得被表述为已确认可读，单项拒绝或无数据必须如实显示。
HealthKit 数据仍不得进入自动备份或手动导出。

## 10. 植物模块政策

### 10.1 Lv.4 基础解锁状态

植物基础能力首发包含在成长线里，但在 Lv.4「生命树冠」解锁：

* Lv.1–3：不显示添加植物入口、植物 tab、植物 quest、FunctionMenu 植物组或植物详情直达入口。
* Lv.1–3：点击植物 route / FunctionMenu 入口时 redirect 到 Growth Roadmap，锁定文案为「生命树冠 Lv.4 解锁植物照护」。
* Lv.4：显示添加植物入口、植物 Dashboard、详情、日志、照片、资料库搜索和本地提醒。
* Lv.4：生成基础植物 quest 和今日任务，可参与植物心情/负反馈信号。
* 已有植物数据：即使当前低于 Lv.4，也 grandfather，继续允许进入植物列表和详情，避免数据被隐藏。
* Onboarding 不采集城市/地区、通知意向或家庭偏好；这些信息只在相关功能中按需询问，也不等于 Lv.1 立即显示植物入口。
* 不启用 CloudKit、真实 AI 识别或天气联动；Personal 只在 Lv.4 成长门之后裁决活跃数量和高级本地能力

首发必须保留：

* Plant 模型
* 数据层
* FeatureGate
* 测试地基
* 未来迁移空间

### 10.2 Free 与 Personal 状态

Lv.4 后 Ohana Free 能完成五株活跃植物的基础照护：

| 功能 | Free | Personal |
| --- | --- | --- |
| 活跃植物 | 最多 5 株 | 不限 |
| 浇水、施肥、修剪、换盆记录 | 是，记录条数不限 | 是 |
| 植物照片 | 基础能力 | 包含 Free |
| 普通植物提醒 / 计划 | 与全 app 共用 3 个普通活跃额度 | 不限 |
| 历史记录查看、编辑和手动导出 | 永久可用 | 包含 Free |
| 自动 iCloud Drive 备份 | 最新一份 | 多版本与恢复点 |
| 植物加入岛屿氛围 | 是 | 包含 Free |
| 高级本地趋势、报告、搜索与批量操作 | 否 | 是，仅已实现能力可对外销售 |

Lv.5「绿洲收益」不解锁基础植物管理，只解锁植物与绿洲/岛屿氛围的奖励联动，例如照护让岛屿更繁茂、装饰或收益反馈。

达到 5 株活跃植物上限时，可以在“再添加一株”的自然场景介绍 Personal；不得限制用户继续照护已有植物、查看或编辑历史、手动导出或处理健康关键事项。

### 10.3 植物付费能力

植物付费能力分为本地规模 / 效率、协作和智能三类。

| 能力 | 归属 |

## 11. AI 能力边界

AI 不是首发核心。
未来 AI 能力进入 Ohana Care+，但必须遵守以下边界。

可做

* 照护记录总结
* 异常趋势提醒
* 兽医就诊前摘要
* 宠物体重 / 饮水 / 排便变化趋势
* 照片纪念册文字
* 植物识别
* 植物病害风险提示
* 季节性养护建议

不可做

* 给出兽医诊断结论
* 替代专业医疗建议
* 制造恐惧式付费转化
* 将健康关键提醒放入付费墙
* 将用户历史数据作为订阅筹码

AI 的表达必须是：

“这里有异常趋势，建议联系兽医 / 专业人士。”

而不是：

“它得了某种病。”

## 12. 非目标与产品红线

Ohana 不是什么，和 Ohana 是什么同样重要。

| 非目标 | 说明 |
| --- | --- |
| 不是兽医诊断 app | 可以记录症状、整理趋势、提醒就医，但不做诊断结论 |
| 不是重度游戏 | 游戏化服务于照护习惯，不反客为主 |
| 不是公开社交网络 | 本机家庭分工与未来联网家庭协作都属于私域，不做公开社区首发 |
| 不是儿童 / 老人监管系统 | 人类档案是轻照护记录，不进入高合规监护场景 |
| 不是专业财务软件 | Expenses 是养宠成本记忆，不做复杂财务会计 |
| 不是云同步优先产品 | 首发信任来自本地稳定和备份可靠 |
| 不是卖焦虑的 app | 不用“你不订阅就会失去数据 / 错过照护”这类恐惧营销 |
| 不是广告流量产品 | 不植入广告，也不出售去广告权益 |
| 不是故意制造痛苦的残缺免费版 | Free 有活跃对象和普通计划额度，但基础记录、健康关键提醒、已有历史、手动导出和纪念仍完整可用 |
| 不是只靠数量扩容的 Plus | Personal 同时提供高级用药计划、长趋势、报告、搜索、自动化和备份版本等个人实用价值 |

产品红线：

* 不锁原始记录或已有历史数据
* 不锁纪念模式
* 不锁健康关键提醒
* 不锁已有数据的手动导出
* 不卖椰子
* 不植入广告或售卖去广告
* 不因取消订阅惩罚本地用户
* 不把离世宠物作为付费转化场景
* 不把基础照护变成付费墙
* 不在降级时自动删除、隐藏、归档或停用超额档案和计划
