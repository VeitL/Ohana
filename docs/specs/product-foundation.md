## 1. 产品是什么

Ohana（夏威夷语“家人”——家人意味着没有人会被落下）是一个把“家”做成一座岛屿的照护应用：家庭成员（宠物为核心，也包括人和植物）住在岛上，日常照护被记录、被提醒、被奖励，最终沉淀为这个家的记忆与资产。

核心定义——家庭即生命组合：家庭不是“人类之间”的概念。任何多于一个生命的组合就是一个家庭——一个人和一只猫、一个人和三盆植物、一对夫妻和一条狗，都是完整的家庭/岛屿。
由此推论：心情、周报、名册、连胜、排行榜等一切“家庭感”功能不以多人类为前提；产品永远不得出现“添加更多人类成员才完整”的暗示。付费墙挡的是“多操作者协作”和“跨设备安心服务”，不是“家庭”本身。

一句话定位：

认真记录照护的家庭，值得一座越来越繁茂的岛。

产品的情感弧线：

日常（喂食、遛狗、清洁、用药）
→ 习惯（连胜、任务、提醒）
→ 惊喜（椰子、扭蛋、绿洲生长）
→ 沉淀（相册、里程碑、账本、周报）
→ 告别与铭记（彩虹桥、纪念模式）

最后一环是 Ohana 区别于工具型记录 app 的灵魂：这个 app 陪用户走完和宠物的一生。

## 2. 为谁做（首发画像）

* 主理人：家庭中承担主要照护责任的那个人，用自己的 iPhone 记录全家。
* 首发场景为单设备、单操作者、纯本地。
* 人类成员是被照护档案对象，不是首发阶段的 app 操作者；单主人版允许建立多个人类档案。
* 植物进入首发成长线，但不在 Lv.1 立即展示；基础植物照护在 Lv.4「家庭树冠」解锁，通过 PlantFeatureGate + PlantUnlockPolicy 控制可达面。
* 养宠家庭是 Lv.1–3 核心；养植物家庭在 Lv.4 扩展进入同一个家庭生命照护闭环。犬、猫为第一公民动物物种，其他动物使用通用浅模板。
* 商业模式采用信任型 Freemium：
    * Ohana Solo：单设备 / 单主人 / 本地照护闭环永久免费。
    * Ohana Family：多设备同步 + 多主人协作付费。
    * 未来 Ohana Care+：AI、智能洞察、植物智能照护等高级能力，可作为更高阶付费层。

## 3. 根本决策（宪法条款）

| # | 决策 | 内容 | 直接后果 |
| --- | --- | --- | --- |
| D1 | 产品定位 | 家中所有生命首发成长线。Lv.1–3 先完成宠物核心照护习惯；Lv.4「家庭树冠」把家庭扩展到植物，开放本地免费档案、任务、提醒、日志和资料库闭环。 | App Store 首发定位为家庭生命照护；onboarding 可采集宠物/儿童安全和植物偏好；基础植物不付费、不限量，但不在 Lv.1 抢占宠物核心习惯。 |
| D2 | 游戏化角色 | 记录为主，游戏化为留存引擎。椰子、连胜、绿洲、扭蛋用于强化照护习惯，但不做重度养成；真钱购买椰子暂不规划。 | 经济必须自洽防刷；冷却、每日预算、距离门槛等机制升格为产品规则；不引入付费货币合规负担。 |
| D3 | 钱包模型 | 成员钱包 + 岛屿储备 + 岛屿总账。照护等有明确归属的奖励进入成员独立钱包；不属于任何成员的系统赠礼进入 `system:island` 岛屿储备。岛屿总资产 = 岛屿储备 + 所有活跃成员钱包；排行榜只表达成员贡献。 | QuestManager 总余额必须恒等于 `system:island + Σ活跃成员 balance`；`system:legacy` 仍只作历史兼容且不计入正式资产；账本可重放；前台默认弱化复杂分账。 |
| D4 | 首发联网范围 | 首发为纯本地 Solo + 用户自有 iCloud Drive 受限备份/恢复；没有 Ohana 账号、Apple/Google 登录或开发者托管后端。CloudKit 实时同步与家庭共享仍由独立能力门控制并保持关闭。 | 离线用户可建档、照护、提醒、奖励、备份和恢复；系统 iCloud 身份只服务 iCloud Drive 文件能力，不等于 App 登录。 |
| D5 | 本机任务与在线协作边界 | Ohana Solo 允许主理人在同一设备用 Human 档案记录家庭分工；普通分工默认 0 奖励并可直接完成，只有用户主动添加正数椰子奖励时才进入提交与发布者确认。这些角色是本地流程状态，不代表账号、远程操作者或对方已收到通知。远程邀请、跨设备实时共享/通知和权限仍属于真正在线协作。 | 本机家庭分工不经过 OnlineFeatureGate；外部协作路由、邀请、共享提醒、远程身份与权限继续受 OnlineFeatureGate 约束。奖励分工发布时须有足额余额，但发布不扣款、不冻结或托管，只有发布者确认完成时才执行转账。界面只呈现当前需要的下一步，不同时暴露负责人、完成人、审核人等整套角色。 |
| D6 | 首发模块范围 | 核心闭环必须成熟，不等于所有模块完整深度都上。首发优先打磨：建宠物 → 记录 → 提醒 → 奖励 → 首页反馈 → 备份。 | P0 必须成熟；P1 可轻量上；P2 可隐藏或保留代码但不要求完整体验。 |
| D7 | 纪念模式 | 照护只读，回忆可写。宠物 / 人类离世后，从所有活跃照护流程退场，不再生成任务、提醒、quest、奖励、连胜、心情信号；钱包冻结、历史保留。但允许新增纪念内容，如照片、回忆文字、纪念日、悼念笔记。 | 离世成员不得新增/编辑照护事实，不得补记历史照护事实，不触发任何经济或照护派生；纪念内容不进入经济系统。 |
| D8 | 删除哲学 | 确认后物理真删。删除成员时必须明确告知不可撤回；确认后物理删除该成员及其从属记录。取消用户可见软删除、回收站、30 天恢复。 | CloudSync 未来可保留用户不可见、不可恢复的 sync tombstone 元数据传播删除，但不得形成恢复 UI 或删除中转态。 |
| D9 | 免费/付费边界 | 信任型 Freemium。Ohana Solo 永久免费，提供完整本地照护闭环；Ohana Family 付费购买多设备同步、多主人协作和长期资产保护；未来 Care+ 购买高级智能能力。 | 付费墙挡的是“多人多设备的安心协作”和“高级智能”，不是认真照护一个生命的权利。 |
| D10 | 多人类档案与本机默认归属 | 单主人版允许建立多个人类档案。`currentActiveHumanId` 只是本机默认的任务视角与记录归属，不是操作者账号或登录身份。执行照护、记录数据或查看待办时优先无感使用该默认值。 | 没有在世 Human 时不伪造归属，只有 1 位时自动归属；两种情况都隐藏执行、记录、领取和审核等无意义控件。2 位以上时才提供轻量的单次覆盖，且覆盖只作用于本次操作，不改写全局默认。主动创建 Human 时姓名必填，性别和生日可选；不读取 Apple 账号资料，不以姓名或邮箱自动创建/合并档案。未来操作者身份仍须与 Human 分层。 |
| D11 | 备份命脉 | 自动 + 手动双保险。默认开启定期自动备份到用户 iCloud Drive 文件；同时提供手动导出存档。两者使用统一的受限导出边界，不包含人类健康/HealthKit、PIN 机密和其他明确禁止离机的数据。备份失败必须可见，不许静默失效。 | 单机版数据安全的唯一防线；换机/丢机可恢复是免费版信任基石，但不得用“完整”掩盖已批准的隐私排除。 |
| D12 | 补记奖励 | 补记历史记录照常奖励，但按操作日预算与冷却结算。补记 30 天前的 100 次喂食，最多拿到今天预算内的椰子。 | 诚实补记不受罚，刷子被预算兜住；发奖以 operation time 而非 record time 结算。 |
| D13 | 余额不足 | 不可透支 + 允许岛屿合资。任何钱包永不出现负余额；一般成员消费可选择从其他成员钱包补差额。Oasis 生命树注入是岛屿级消费，自动使用全部正式可用椰子：先扣岛屿储备，再按确定顺序由活跃成员钱包补足，并逐账户记录流水。 | 所有出资与扣款必须在同一事务中成功或整体回滚；账本仍可重放；排行榜贡献度语义不被污染。 |
| D14 | 预算触顶感知 | 温和透明。触顶后照护记录正常完成且有完成反馈，奖励位置显示温和文案，例如“今日椰子已装满，明天继续～”。 | 不隐瞒、不说教、不预告剩余额度；避免用户把限额当 bug，也不鼓励掐预算刷。 |
| D15 | 通知哲学 | 克制预算制。通知分三级：健康关键 > 日常照护 > 氛围提醒。健康关键不受每日限额；日常和氛围通知受限额、合并和夜间免打扰约束。 | 任何新通知必须先归类定级；通知预算表写入 Notifications-logic.md。 |
| D16 | 删除同步元数据 | 无用户可见回收站。未来 CloudSync 传播删除时，只允许保留不可见、不可恢复的 sync tombstone 元数据。 | tombstone 是同步协议事实，不是产品恢复能力。 |
| D17 | 首次体验 | 极简宠物优先。建岛 → 建第一只宠物 → 完成第一笔照护记录 → 获得不绑定成员的一次性岛屿启动赠礼 → 看到绿洲种子发芽。主理人档案可跳过/后补，90 秒内完成价值闭环。 | 启动赠礼进入 `system:island`，不得写入 Pet/Human 钱包；全部正式可用椰子都可用于生命树注入；Onboarding 规则书按此脚本展开；“加入岛屿”路径首发隐藏。 |
| D18 | 物种分层 | 犬猫深 + 其他浅。犬猫为第一公民；其他动物使用通用照护模板，不适用的深功能自动隐藏。 | 每本规则书标注模块的物种适用性。 |
| D19 | 植物功能门 | 植物收进独立产品门和成长解锁门。PlantFeatureGate 表示当前 build 支持植物；PlantUnlockPolicy 决定用户可见性：Lv.4「家庭树冠」解锁，已有植物数据 grandfather。 | 基础植物照护不依赖账号、联网、CloudKit 或付费墙；Lv.1–3 植物入口 redirect 到 Growth Roadmap；未来只把高级智能/协作接到独立能力门。 |
| D20 | 多语言扩展就绪 | 当前九语言架构保持；新增语言的成本边界必须收敛为翻译资源文件 + 注册表若干 case + 商店元数据。 | 不允许功能代码散落语言判断；新增语言不应改业务逻辑。 |
| D21 | 植物商业边界 | 基础植物照护免费但通过成长解锁。Lv.4 后植物档案、浇水、施肥、修剪、换盆、照片、基础提醒、历史记录、资料库和导出属于 Ohana Solo 免费能力；植物多人协作属于 Ohana Family；AI 识别、病害分析、天气联动、季节计划、智能养护建议属于未来 Care+。 | 不卖“添加植物权限”或“植物数量限制”；Lv.4 是体验节奏，不是付费墙；付费只购买协作、同步和智能增强。O8 关闭。 |
| D22 | 数据与付费红线 | 用户取消订阅后，必须仍可查看、编辑、导出本机已有数据；不得锁历史、不得锁纪念模式、不得锁基础提醒、不得按宠物数量收费、不得卖椰子。 | 付费状态变化不得破坏本地照护闭环；付费墙不得伤害信任。 |
| D23 | 产品非目标 | Ohana 不是兽医诊断 app、不是重度游戏、不是公开社交网络、不是专业财务软件、不是儿童/老人监管系统、不是云同步优先产品。 | 所有新增需求必须先判断是否越界；越界功能不得进入首发。 |
| D24 | 首发平台范围 | 首发为 iPhone-only，最低系统 iOS 26.2；不发布原生 iPad 或 watchOS app。配对 Apple Watch 接收并操作由 iPhone 转发的系统通知属于真机兼容性验收，不等于原生 Watch app 支持。 | 所有首发 target 使用 iPhone device family；iPad、原生 Watch、Complication、独立 Watch 同步和更低 iOS 支持分别作为后续迁移，不得混入 RC 收尾。 |
| D25 | 无 App 账号，保留未来扩展边界 | 当前版本不创建开发者托管账号，不提供 Apple/Google 登录，不读取系统账号资料，也不引入 Auth SDK、账号后端、远程会话或账号数据收集。iCloud Drive 备份继续依赖用户自己的系统 iCloud 身份。 | 只有出现跨平台、跨 iCloud 家庭协作或必须由服务器持有的身份事实后，才按 `docs/planning/account-backend-extension.md` 重新立项。未来首次身份页可突出 Apple 登录，但必须允许本地继续；登录只创建/恢复 Account，Human 由用户显式一键确认，三层身份保持分离。资料任务奖励用户完成选择，不能用椰子诱导披露可选敏感信息。规划文档不是现行能力授权。 |
| D26 | 四个顶层区域，一套待办 | 顶层区域固定为“首页 → 待办 → Oasis → 植物”，按成长解锁在末尾追加，不为家庭分工或数据统计新增 Tab。“待办”以清单 / 日历呈现同一套 Event、Reminder 与 FamilyTask 投影；家庭分工是任务属性，不是另一套任务中心。 | 首页只投影 Today Focus 与家庭概况；成员页跳转成员筛选后的待办；对象详情保留档案与对象趋势；植物总览承载植物领域统计；家庭洞察作为首页二级入口；Oasis 不承载必须完成的任务。 |
| D27 | 多对象照护是一笔现实操作 | 批量植物照护和共享宠物照护都遵循“选动作 → 选有效对象 → 一次确认 → 结果摘要 / 一次撤销”。提交前必须重验全部目标，任一目标失效则整批不写；同一次操作用稳定 transaction / session ID 关联对象覆盖记录。 | 统计必须同时区分现实操作次数与对象覆盖次数；一次浇五株是一次劳动、五个对象覆盖。共享猫砂照护形成一个 session、每只猫一份覆盖记录、一次奖励和一次撤销；首发不建立猫砂盆等 CareAsset。 |

## 4. 版本与付费政策

### 4.1 版本结构

| 版本 | 价格策略 | 核心价值 | 包含能力 |
| --- | --- | --- | --- |
| Ohana Solo | 永久免费 | 一个人认真照护一个家庭岛屿 | 本地档案、照护记录、提醒、Human 档案间本机奖励任务、历史、花费、相册、纪念模式、椰子、连胜、Oasis 基础玩法、手动导出、自动 iCloud Drive 文件备份 |
| Ohana Family | 订阅 + 终身买断 | 多设备、多主人、共享照护、家庭资产保护 | CloudKit 同步、家庭岛屿共享、成员身份/权限（若未来需要）、跨设备任务协作、共享提醒、权限管理、活动审计、云端版本历史、安全分享 |
| 未来 Ohana Care+ | 待定，可作为高级订阅或附加层 | 智能照护与长期洞察 | AI 总结、异常趋势、兽医就诊摘要、植物识别、病害分析、天气联动、智能养护计划 |

### 4.2 Ohana Solo 永久免费能力

Ohana Solo 必须永久免费提供完整本地照护闭环：

| 功能 | 免费要求 |
| --- | --- |
| 创建宠物档案 | 免费，不限数量 |
| 基础照护记录 | 免费，不限条数 |
| 喂食、遛狗、清洁、猫砂、健康、用药、花费 | 免费 |
| 本地提醒 | 免费 |
| 本地历史记录 | 免费，不限历史长度 |
| 照片 / Moments | 免费基础能力 |
| 彩虹桥 / 纪念模式 | 免费 |
| 椰子、连胜、Oasis 基础玩法 | 免费 |
| 手动导出 | 免费 |
| 自动 iCloud Drive 文件备份 | 免费 |
| 多个人类档案 | 免费 |
| Human 档案间本机奖励任务 | 免费；由同一设备主理人记录创建、指派、提交与确认 |
| Lv.4 基础植物照护 | 免费 |

免费版不得限制：

* 宠物数量
* 记录条数
* 历史长度
* 基础提醒
* 导出数据
* 纪念模式
* 已有本地数据查看与编辑

### 4.3 Ohana Family 付费能力

Ohana Family 售卖的是安心协作，不是基础照护权限。

| 功能 | 归属 |
| --- | --- |
| 多设备实时同步 | Ohana Family |

## 6. 互通脊柱：业务事实流

用户动作
（首页长按 / QuickCare / 模块页 / 今日任务完成键 / 共享照护）
   ↓
domain service 写入一个 careTransaction
   ↓
单成员照护：通常生成一条业务事实
多成员共享照护：可生成多条子事实，但必须挂在同一个 careTransactionId 下
   ↓
由照护派生执行器统一裁决，且只发生一次：
   ├─ 今日任务勾掉
   ├─ 有归属椰子奖励 → 成员钱包 + 岛屿账本
   ├─ 无成员归属系统赠礼 → 岛屿储备 + 岛屿账本
   ├─ 连胜推进
   ├─ 成就 / 里程碑检查
   ├─ 相关提醒消除
   ├─ 库存 / 粮仓 / 账本派生
   ├─ Oasis XP / 绿洲反馈
   └─ 首页 / 仪表盘 revision 推进

入口可以很多，用户意图只有一个，事务必须唯一，派生只能发生一次。

同一个动作从不同入口完成，结果必须完全一致。
同一事实不得因为首页、QuickCare、任务完成键或模块页重复触发奖励、连胜、任务完成或账本派生。

## 7. 全局不变量

每本模块规则书必须逐条对照以下不变量。

### G1 一意图一事务，一事实只派生一次

一个用户动作必须生成一个唯一 careTransactionId。
单成员照护通常写一条业务事实；多成员共享照护可写多条子事实，但必须挂在同一个事务下。奖励、任务、连胜、提醒消除、库存变更、Oasis XP 等派生不得重复触发。

### G2 余额可重放

任何成员钱包及岛屿储备余额必须可由账本事实流重放推导。
岛屿总资产 ≡ `system:island + Σ活跃成员钱包`；`system:legacy` 不参与正式资产。
禁止任何视图直改余额；禁止绕过 QuestManager 底层奖励管线以及 EconomyRewardDiscipline / CareEventEconomyAwarding 等受审计收口发奖。

### G3 经济受预算管控

所有产出经过冷却 + 每日预算分档：

normal → fatigue 50% → recordOnly 0% → cooldown

记录永远允许，因为记录是产品心跳；被限制的是奖励，不是记录本身。

### G4 离世成员退场

离世成员：

* 数据保留
* 不再生成任务
* 不再生成提醒
* 不再生成 quest
* 不计入心情
* 不计入今日焦点
* 不推进连胜
* 不获得奖励
* 钱包冻结但历史可见
* 成员页可通过显示开关查看

每个模块的规则书必须写明本模块如何对待离世成员。

### G4.1 离世成员写入边界

* active 成员作为照护对象时，可写照护事实。
* 离世成员作为照护对象时，照护写入、编辑、历史补记和照护派生必须 no-op。
* 显式 executor id 不可解析、已被物理删除或不可写时，不得丢失 active 照护对象的事实。
* fallback 归属必须明确：
    * 优先归属可写 active human；
    * 没有可用 owner 时，fact-only 无奖励；
    * 不得伪装为原 executor 发奖。

### G4.2 纪念内容例外

离世成员允许新增纪念内容：

* 照片
* 回忆文字
* 纪念日
* 悼念笔记
* 纪念相册整理

纪念内容不得触发：

* 椰子奖励
* 连胜
* 今日任务完成
* 健康趋势
* 喂食 / 用药 / 遛狗等照护派生
* 活跃成员心情信号

### G5 删除即真删

成员与重要记录删除 = 明确确认后物理删除，用户不可恢复。
未来 CloudSync 仅可保留不可见、不可恢复的 sync tombstone 元数据用于跨设备删除传播，不得作为回收站或恢复能力。

### G6 隐私底线

数据默认仅存本机。
手动导出与自动备份必须完整覆盖“已批准的受限导出范围”，不得导出
人类健康/HealthKit、PIN hash/salt/lockout、自由文本家庭任务和可能重复敏感
文本的派生经济/账本侧车。“完整”不表示可以突破这一隐私边界。
“删除一切数据”为立即删除应用管理的本地用户内容、附件、偏好和反滥用
记录，不走回收站。对应用管理的 iCloud Drive 自动备份，删除失败必须显示
待清理状态并可重试；用户已主动分享或移出应用沙盒的副本不在远程擦除
承诺内。

### G7 单机自洽

首发版本不允许出现任何需要“另一个在线用户”才能完成或才有意义的流程：

* 邀请
* 加入岛屿
* 向远程操作者指派或推送任务
* 多人通知
* 实时协作
* 认领档案

这些能力必须收进 OnlineFeatureGate。

同一设备的本机家庭分工是记录能力，不是上述在线协作：主理人可用不同 Human
档案记录创建、执行和确认，但这些动作不证明对应人物实际操作或收到通知。普通分工
默认 0 奖励并直接完成；只有用户主动添加正数奖励时，才在余额足够的前提下进入提交 /
确认流程。发布只记录承诺，不扣款、不冻结、不形成 escrow，发布者确认完成时才从其
钱包转给完成者。远程邀请、跨设备实时共享/通知和权限仍须经过 OnlineFeatureGate。

### G8 工程质量

流畅性、本地化、无障碍、启动路径、能耗、架构隔离等遵循 AGENTS.md。
本文不重复工程细则，模块规则书引用即可。

### G9 家庭自洽

一个生命 + 主理人即完整家庭。
任何家庭感功能在单人单宠场景下必须完整成立，不残缺、不冷场、不暗示“添加更多成员才完整”。
排行榜在只有一个成员时应有得体的单成员形态。

### G10 备份命脉

自动备份默认开启。
备份失败必须对用户可见。
恢复路径必须被测试覆盖：

备份 → 擦除 → 恢复 → 数据完整

“陪你走完宠物一生”的产品承诺以此为底。

### G11 备份与删除一致性

应用内删除是当前数据库的不可恢复删除。
自动备份只保留有限版本，并在下一次成功备份后覆盖删除前状态。
手动导出的存档属于用户自持文件，应用不承诺远程擦除。
恢复旧存档前必须提示：

该存档可能包含你之后已经删除的数据。

### G12 付费状态不破坏本地数据

取消订阅、试用结束、购买失败、恢复购买失败，都不得破坏本机已有数据。
最多停止云同步、协作、共享提醒、云端版本历史和高级智能能力。
本地查看、编辑、导出、基础提醒、纪念模式必须继续可用。

### G13 植物功能门独立

PlantFeatureGate 与 OnlineFeatureGate 不得耦合。
植物基础能力在 Lv.4 免费开放，也可以单独给 Care+ 增加智能能力；不得因为联机未解锁而阻止已解锁或 grandfather 的本地基础植物照护。

### G14 费用事实金额有效

用户输入、共享分摊、保费和文档派生费用必须是大于 0 的有限数字；0、负数、NaN
和正负无穷不得进入业务事实、导入或恢复。唯一负向例外是保险领域命令根据大于
0 的理赔金额生成的报销事实；它必须使用保险费用分类和稳定的报销标记，不得由
通用费用 UI 或通用费用命令伪造。失败必须发生在写入前，并允许用户修正后重试。

### G15 HealthKit 运动是只读外部事实

HealthKit 授权后，Human Workout 页面直接查询并展示当前可读的活动摘要与
`HKWorkout`，不要求用户再次导入，也不把只读 HealthKit 行伪装成 Ohana 可删除
记录。Ohana 手动运动和已完成遛狗保持各自的本地事实来源；统一 read model 按
HealthKit UUID、PetWalk ID 及时间、时长、距离匹配去重。既有本地 HealthKit / PetWalk
副本不得自动删除；实时来源可用时由其覆盖展示，来源不可用时允许本地副本兜底。
读取授权状态不得被表述为已确认可读，单项拒绝或无数据必须如实显示。
HealthKit 数据仍不得进入自动备份或手动导出。

## 10. 植物模块政策

### 10.1 Lv.4 基础解锁状态

植物基础能力首发包含在成长线里，但在 Lv.4「家庭树冠」解锁：

* Lv.1–3：不显示添加植物入口、植物 tab、植物 quest、FunctionMenu 植物组或植物详情直达入口。
* Lv.1–3：点击植物 route / FunctionMenu 入口时 redirect 到 Growth Roadmap，锁定文案为「家庭树冠 Lv.4 解锁植物照护」。
* Lv.4：显示添加植物入口、植物 Dashboard、详情、日志、照片、资料库搜索和本地提醒。
* Lv.4：生成基础植物 quest 和今日任务，可参与植物心情/负反馈信号。
* 已有植物数据：即使当前低于 Lv.4，也 grandfather，继续允许进入植物列表和详情，避免数据被隐藏。
* Onboarding 可以采集城市/地区、通知意向、宠物/儿童安全偏好、植物经验和主要护理场景，但不等于 Lv.1 立即显示植物入口。
* 不启用 CloudKit、真实 AI 识别、天气联动或付费墙

首发必须保留：

* Plant 模型
* 数据层
* FeatureGate
* 测试地基
* 未来迁移空间

## 11. AI 能力边界

AI 不是首发核心。
未来 AI 能力进入 Ohana Care+，但必须遵守以下边界。

可做

* 照护记录总结
* 异常趋势提醒
* 兽医就诊前摘要
* 宠物体重 / 饮水 / 排便变化趋势
* 照片纪念册文字
* 植物识别
* 植物病害风险提示
* 季节性养护建议

不可做

* 给出兽医诊断结论
* 替代专业医疗建议
* 制造恐惧式付费转化
* 将健康关键提醒放入付费墙
* 将用户历史数据作为订阅筹码

AI 的表达必须是：

“这里有异常趋势，建议联系兽医 / 专业人士。”

而不是：

“它得了某种病。”

## 12. 非目标与产品红线

Ohana 不是什么，和 Ohana 是什么同样重要。

| 非目标 | 说明 |
| --- | --- |
| 不是兽医诊断 app | 可以记录症状、整理趋势、提醒就医，但不做诊断结论 |
| 不是重度游戏 | 游戏化服务于照护习惯，不反客为主 |
| 不是公开社交网络 | 本机家庭分工与未来联网家庭协作都属于私域，不做公开社区首发 |
| 不是儿童 / 老人监管系统 | 人类档案是轻照护记录，不进入高合规监护场景 |
| 不是专业财务软件 | Expenses 是养宠成本记忆，不做复杂财务会计 |
| 不是云同步优先产品 | 首发信任来自本地稳定和备份可靠 |
| 不是卖焦虑的 app | 不用“你不订阅就会失去数据 / 错过照护”这类恐惧营销 |
| 不是宠物数量收费 app | 多宠家庭不是高级用户，是普通家庭 |

产品红线：

* 不锁历史数据
* 不锁纪念模式
* 不锁基础提醒
* 不锁导出
* 不卖椰子
* 不按宠物数量收费
* 不因取消订阅惩罚本地用户
* 不把离世宠物作为付费转化场景
* 不把基础照护变成付费墙
