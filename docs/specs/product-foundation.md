# Ohana 产品基石（Product Foundation）

> **地位声明**：本文档是 Ohana 的产品宪法，是所有模块规则书（`docs/specs/<模块>-logic.md`）、测试验收、对抗复审的**最高裁判标准**。模块行为与本文冲突即为 bug。本文的每条决策由产品主人拍板（2026-06-12 两轮确认）；修改本文必须经产品主人逐条确认，AI 会话不得自行改写决策条款。
>
> 规则优先级：用户当前指令 > 本文档 > `AGENTS.md`（工程规则）> 模块规则书 > 代码现状。本文管"产品应该是什么"，AGENTS.md 管"代码应该怎么写"，互不越界。

---

## 1. 产品是什么

**Ohana**（夏威夷语"家人"——家人意味着没有人会被落下）是一个把"家"做成一座**岛屿**的照护应用：家庭成员（宠物为核心，也包括人和植物）住在岛上，日常照护被**记录**、被**提醒**、被**奖励**，最终沉淀为这个家的**记忆与资产**。

> **核心定义——家庭即生命组合**（2026-06-12 产品主人澄清）：家庭不是"人类之间"的概念。**任何多于一个生命的组合就是一个家庭**——一个人和一只猫、一个人和三盆植物、一对夫妻和一条狗，都是完整的家庭/岛屿。由此推论：心情、周报、名册、连胜等一切"家庭感"功能**不以多人类为前提**；产品永远不得出现"添加更多人类成员才完整"的暗示。付费墙挡的是"多操作者协作"（多人多设备），不是"家庭"本身。

一句话定位：**认真记录照护的家庭，值得一座越来越繁茂的岛。**

产品的情感弧线：日常（喂食遛狗）→ 习惯（连胜、任务）→ 惊喜（椰子、扭蛋、绿洲生长）→ 沉淀（相册、里程碑、账本）→ 告别与铭记（彩虹桥、纪念模式）。最后一环是 Ohana 区别于工具型记录 app 的灵魂：**这个 app 陪用户走完和宠物的一生。**

## 2. 为谁做（首发画像）

- **主理人**：家庭中承担主要照护责任的那个人，用自己的 iPhone 记录全家。
- 首发场景为**单设备单操作者**；人类成员和植物是被照护的档案对象，不是 app 操作者。允许建多个人类档案（D10），联机版上线后档案可被"认领"升级为真实操作者。
- 养宠家庭为绝对核心；犬、猫为第一公民物种，其他物种通用浅模板（D18）。
- **版本与商业模式**：单机/单主人版 = **永久免费且全功能**（D9）；联机/多主人版（多设备多操作者协作）= 付费，订阅 + 终身买断双轨（D9）。

## 3. 八条根本决策（宪法条款，已拍板）

| # | 决策 | 内容 | 直接后果 |
|---|---|---|---|
| **D1** | 产品定位 | **宠物首发，全家是愿景**。首发以宠物照护为绝对核心保证体验深度；人类/植物功能保留但低调，"全家照护中心"作为长期方向逐版本补强 | App Store 定位宠物类目；onboarding 以宠物开场；文案、空状态、深度功能优先宠物 |
| **D2** | 游戏化角色 | **中间路线**。记录为主、游戏化为重要留存引擎：经济必须自洽防刷（否则奖励失去意义），但不做重度养成；真钱购买椰子暂不规划 | 现有冷却/每日预算/距离门槛机制升格为宪法（见 G3）；不引入付费货币合规负担 |
| **D3** | 钱包模型 | **成员钱包 + 岛屿总账**。每个成员是独立钱包（谁的照护赚的归谁，人/宠按 2/3 与 1/3 分账），岛屿总资产 = 所有成员钱包之和，排行榜体现"谁最勤"；消费从对应成员钱包扣除 | `QuestManager` 总余额必须恒等于 Σ成员 balance（不变量测试）；财富页排行榜语义为贡献度 |
| **D4** | 首发联网范围 | **首发纯单机** + 本地备份/恢复。CloudSync 代码（dirty/tombstone/记录状态）作为地基保留但**不启用**；iCloud 同步与家庭共享在 1.x 解锁 | 验证成本最低、审核风险最小；release-hardening-plan 冻结范围维持有效 |
| **D5** | 协作功能门 | **FamilyTasks 及一切"真协作"功能（指派、邀请、悬赏）只在联网模式解锁后出现，首发隐藏**。单机模式 = 主理人模式，不存在"指派给看不到通知的人"这种伪协作 | FamilyTasks 首发不可达；onboarding"加入岛屿"路径隐藏；家庭周报中依赖悬赏/分工的部分随之处理（见 §7） |
| **D6** | 首发模块范围 | **核心全上 + 裁剪清单**。核心体验链全部上架；按 §7 裁剪清单隐藏与单机模式矛盾或拖低整体成熟度的模块 | 隐藏 ≠ 删除：feature flag / 路由不可达，代码保留 |
| **D7** | 纪念模式 | **完整纪念模式**。宠物离世：数据全保留；从所有活跃流程退场（不再生成任务/提醒/quest，不计入心情）；钱包冻结、历史保留；卡片从主堆退场但有专门纪念入口；**可撤销**（标错了能完整恢复） | 每本模块规则书必须有"离世成员行为"条目（G4） |
| **D8** | 删除哲学 | **软删除 + 30 天回收站**。删除成员/重要记录进 tombstone 回收站，期内可恢复，期满真正清理；与云同步 tombstone 机制天然一致 | "危险区域"的级联真删改为软删除；"删除一切数据"（隐私权）仍为立即真删（G6） |

**第二批决策（2026-06-12 全局遍历，三轮拍板）：**

| # | 决策 | 内容 | 直接后果 |
|---|---|---|---|
| **D9** | 免费/付费边界 | **单机全功能免费**：单主人版不设任何限额（宠物数/记录数/历史长度）。付费只买"多设备同步 + 多主人协作"，形态为**订阅 + 终身买断双轨**（主推年订阅，提供较贵的终身买断） | EntitlementService 只有一个判定维度：联机协作是否解锁；免费体验是产品口碑的基石 |
| **D10** | 多人类档案 | 单主人版**允许建多个人类档案**（被照护者：配偶/孩子的体重、用药、生日都可记录）。联机版上线后，档案可被真实用户**认领**为操作者账号 | Human 模型需预留"已认领/未认领"的演进空间；认领细节为开放问题 O6 |
| **D11** | 备份命脉 | **自动 + 手动双保险**：默认开启定期自动备份到用户 iCloud Drive（**文件形式**，不是 CloudKit 同步，不违反 D4）+ 随时手动导出存档。备份失败必须可见，不许静默失效 | 单机版数据安全的唯一防线；换机/丢机可恢复是免费版的信任基石（G10） |
| **D12** | 补记奖励 | **补记历史记录照常奖励**，但奖励**计入操作当日的预算与冷却**（补记 30 天前的 100 次喂食，最多拿到今天预算内的椰子）。诚实补记不受罚，刷子被预算兜住 | 与 D2 的调和点；规则书须验证发奖以"操作时间"而非"记录时间"结算 |
| **D13** | 余额不足 | **不可透支 + 允许岛屿合资**：任何钱包永不出现负余额；消费时对应成员余额不足，可选择从其他成员钱包补差额，账本记一笔转账事实 | 合资是转账事实，账本仍可重放（G2）；排行榜贡献度语义不受污染 |
| **D14** | 预算触顶感知 | **温和透明**：触顶后照护记录正常完成且有完成反馈，奖励位置显示温和文案（"今日椰子已装满，明天继续～"）。不隐瞒、不说教、不预告剩余额度 | 永不让用户把限额当成 bug；也不暴露"账篷"鼓励掐预算刷 |
| **D15** | 通知哲学 | **克制预算制**：通知分三级——健康关键（用药/疫苗/断粮，不受限额）> 日常（喂食/提醒）> 氛围（周报/连胜保护）；每日总量限额 + 同类合并 + 默认夜间免打扰。具体预算表由 Claude 设计、产品主人审 | 规则书阶段产出预算表（P1）；任何新通知必须先归类定级 |
| **D16** | 回收站范围 | **成员 + 珍贵档案进回收站**（宠物/人/植物、照片/时刻、文档/保单、批量清空操作）；单条高频流水（一次喂食/一条体重）二次确认后直删——但**底层仍写 tombstone**（供未来同步），只是不进回收站 UI | 回收站保持"只放珍贵东西"的信噪比 |
| **D17** | 首次体验 | **极简宠物优先**：建岛 → 建第一只宠物 → 引导完成第一笔照护记录 → 获得第一把椰子 + 看到绿洲种子发芽（aha 时刻）。主理人档案可跳过/后补，**90 秒内完成价值闭环** | Onboarding 规则书按此脚本展开；"加入岛屿"路径首发隐藏（§7） |
| **D18** | 物种分层 | **犬猫深 + 其他浅**：犬猫为第一公民（全功能 + 专属体验如遛狗 GPS、猫砂追踪）；其他物种用通用照护模板（喂食/清洁/健康/花费可用），不适用的深功能自动隐藏 | 每本规则书标注模块的物种适用性；O3 关闭 |

## 5. 互通脊柱：业务事实流（产品视角）

```
用户动作（任何入口：首页长按 / QuickCare / 模块页 / 任务"完成"键）
   ↓
domain service 写【一条业务事实】（PetCareLog / PetFoodRecord / WalkLog / …）
   ↓ 由服务同步派生（用户无感，但必须全部发生且只发生一次）：
   ├─ 今日任务勾掉（TodayFocus quest 完成）
   ├─ 椰子奖励 → 对应成员钱包 + 岛屿账本（经预算/冷却裁决，D2/D3）
   ├─ 连胜推进（DailyStreak）
   ├─ 成就/里程碑检查（Achievements/Milestones/GrowthUnlock）
   ├─ 相关提醒消除（Calendar/Notifications）
   ├─ 绿洲生长 XP（Oasis）
   └─ 首页/仪表盘读模型刷新（revision 推进）
```

**入口可以很多，事实只有一条，派生只发生一次。** 同一个动作从不同入口做，结果必须完全一致——这是全部模块规则书的第一裁判标准。

## 6. 全局不变量（每本模块规则书必须逐条对照）

- **G1 一动作一事实一次奖励**：一个用户动作写一条业务事实；同一事实绝不触发两次派生（奖励/任务/连胜）。不同入口做同一动作，结果恒等。
- **G2 余额可重放**：任何成员钱包余额必须可由账本事实流重放推导；岛屿总资产 ≡ Σ成员钱包。禁止任何视图直改余额；禁止绕过 `CoconutEconomyService`/`QuestManager` 管线发奖。
- **G3 经济受预算管控**：所有产出经过冷却 + 每日预算分档（normal → fatigue 50% → recordOnly 0% → cooldown）；记录永远允许（记录是产品心跳），被限的只是奖励。防刷靠预算不靠禁止记录。
- **G4 离世成员退场**（D7）：数据保留；不再生成任务/提醒/quest；不计入心情与今日焦点；钱包冻结但历史可见；可完整撤销。每个模块的规则书必须写明本模块如何对待离世成员。
- **G5 删除即软删**（D8）：成员与重要记录删除 = tombstone 进回收站，30 天可恢复，期满清理；可同步模型不物理删除。
- **G6 隐私底线**：数据默认仅存本机；导出必须完整覆盖用户数据；"删除一切数据"（设置中的隐私权操作）为立即真删，不走回收站。
- **G7 单机自洽**（D4/D5）：首发版本不允许出现任何需要"另一个在线用户"才能完成或才有意义的流程（邀请、加入岛屿、指派通知、实时协作）。
- **G8 工程质量**：流畅性、本地化（九语言）、无障碍、启动路径等遵循 `AGENTS.md`——本文不重复，规则书引用即可。
- **G9 家庭自洽**：一个生命 + 主理人即完整家庭（§1 核心定义）。任何"家庭感"功能（心情/周报/名册/连胜/排行榜）在单人单宠场景下必须完整成立、不残缺、不出现"添加更多成员才能解锁"的暗示。排行榜在只有一个成员时应有得体的单成员形态。
- **G10 备份命脉**：自动备份默认开启（D11），备份失败对用户可见；恢复路径必须被测试覆盖（备份→擦除→恢复→数据完整）。"陪你走完宠物一生"的产品承诺以此为底。

## 7. 首发裁剪清单（D6 的执行细则）

| 模块/路径 | 决定 | 理由 | 状态 |
|---|---|---|---|
| 联机面整体：FamilyTasks 全部入口 + 设置页云同步区块 + CKShare 邀请/接受路径 | **统一收进 `OnlineFeatureGate` 功能门**（首发恒关闭；门即未来 EntitlementService 雏形） | D5/D9/G7；经核实 Onboarding 并无独立"加入岛屿"路径，联机面实际在 CKShare 与设置层 | ✅ 已拍板（GAP-1） |
| FamilyReports 周报 | **保留照护周报，剥离悬赏榜**（悬赏随联机门隐藏；剥离成本过高则上报再议） | 周报对单主人有价值且强化 G9 家庭感；悬赏依赖 FamilyTasks | ✅ 已拍板 |
| 其余全部模块 | **保留上架** | 核心链（记录→提醒→经济→档案→纪念）完整；Plants/Human 侧按 D1 低调保留 | ✅ 已拍板 |

> 裁剪 = feature flag / 路由不可达 + 入口移除，代码与测试保留。隐藏模块仍要过基本门禁（编译、不被意外路由到），但不要求 🏁 成熟度。
